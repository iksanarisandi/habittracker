Version	Date	Status

1. Executive Summary
Pelacak Kebiasaan Harian adalah aplikasi Android minimalis yang membantu pengguna membangun kebiasaan positif melalui tracking konsisten, visualisasi progres, dan reminder pintar. Aplikasi ini dirancang sebagai MVP (Minimum Viable Product) yang siap produksi dengan fokus pada kesederhanaan, kecepatan, dan pengalaman offline-first.

1.1 Problem Statement
Banyak pengguna kesulitan membangun kebiasaan baru karena:
•	Aplikasi habit tracker terlalu kompleks (terlalu banyak fitur yang tidak terpakai)
•	Membutuhkan login dan koneksi internet (friction tinggi)
•	Tracking manual memakan waktu dan mudah terlupakan
•	Tidak ada visual progres yang memotivasi

1.2 Solution Overview
Aplikasi ini memberikan solusi dengan:
•	Interface minimalis dengan fokus pada daily checklist
•	100% offline, tanpa akun atau registrasi
•	Streak tracking untuk motivasi berkelanjutan
•	Reminder pintar yang tidak mengganggu
•	Widget home screen untuk akses instant

1.3 Success Metrics
MVP dianggap berhasil jika mencapai:
•	Daily Active Users (DAU) retention rate > 40% setelah 7 hari
•	Average session duration 30-60 detik (cepat, efisien)
•	User membuat minimal 3 habit dalam minggu pertama
•	Crash rate < 1% pada production
•	App rating > 4.2 di Play Store setelah 100+ reviews

5. Data Architecture & Database Schema
5.1 Technology Stack
Database: Room Database (SQLite wrapper for Android)
ORM: Room with Kotlin Coroutines for async operations
Migration Strategy: Room Auto-Migration with @AutoMigration annotation
Backup: Local export to app-specific storage (no cloud backup in MVP)

5.2 Database Schema (Room)
Table: habits
Stores all habit definitions created by user.

Column	Type	Constraints	Description
id	Long	PK, Auto	Unique identifier untuk habit
name	String	NOT NULL	Nama habit (max 50 char)
icon	String	NULLABLE	Icon identifier (e.g. running, book, sleep)
frequency	String	NOT NULL	DAILY atau WEEKLY (enum as string)
reminderTime	String	NULLABLE	Format HH:mm (e.g. 09:00) atau NULL jika no reminder
isReminderEnabled	Boolean	DEFAULT TRUE	Flag untuk enable/disable reminder tanpa hapus time
createdAt	Long	NOT NULL	Timestamp (epoch millis) saat habit dibuat
updatedAt	Long	NOT NULL	Timestamp saat habit terakhir di-update
sortOrder	Int	DEFAULT 0	Urutan custom untuk reordering (future feature)

Indexes:
•	PRIMARY KEY on id
•	INDEX on createdAt for sorting by creation date

Table: habit_logs
Stores completion records for each habit on each date.

Column	Type	Constraints	Description
id	Long	PK, Auto	Unique identifier untuk log entry
habitId	Long	FK, NOT NULL	Reference ke habits.id (CASCADE DELETE)
date	String	NOT NULL	Format YYYY-MM-DD (e.g. 2026-02-01)
completed	Boolean	NOT NULL	TRUE jika habit completed pada date tersebut
completedAt	Long	NULLABLE	Timestamp (epoch) saat user tap complete (untuk analytics)
createdAt	Long	NOT NULL	Timestamp saat log entry dibuat
updatedAt	Long	NOT NULL	Timestamp saat log entry terakhir di-update

Indexes:
•	PRIMARY KEY on id
•	FOREIGN KEY habitId REFERENCES habits(id) ON DELETE CASCADE
•	UNIQUE constraint on (habitId, date) - satu habit hanya bisa punya satu log per hari
•	INDEX on habitId for fast lookup by habit
•	INDEX on date for date-range queries

5.3 Data Logic & Business Rules
Streak Calculation Logic
Streak dihitung dengan algoritma berikut:
41.	Query habit_logs untuk habitId tertentu, sorted by date DESC
42.	Mulai dari hari ini, cek apakah completed = TRUE
43.	Jika TRUE, increment streak dan cek hari sebelumnya (yesterday)
44.	Jika FALSE atau tidak ada log, stop counting → return current streak
45.	Untuk weekly habits, gunakan ISO week number sebagai unit

Pseudo-code:

fun calculateStreak(habitId: Long, frequency: Frequency): Int {
  var streak = 0
  var currentDate = LocalDate.now()
  while (true) {
    val log = getLogForDate(habitId, currentDate)
    if (log?.completed != true) break
    streak++
    currentDate = if (frequency == DAILY) currentDate.minusDays(1)
                  else currentDate.minusWeeks(1)
  }
  return streak
}

Daily Reset Logic
Reset harian dilakukan pada jam 00:00 waktu lokal device:
•	TIDAK menghapus data log (history tetap tersimpan)
•	HANYA mengubah status UI untuk habit hari ini dari completed ke uncompleted
•	Implementation: Check date saat app launch, jika != lastLaunchDate → refresh UI

Timezone Handling
Edge case untuk user yang traveling atau ganti timezone:
•	Gunakan LocalDate berdasarkan device timezone saat ini
•	Log date selalu dalam format ISO 8601 (YYYY-MM-DD) untuk consistency
•	Jika user ganti timezone, streak tetap valid berdasarkan local date

5.4 Database Migration Plan
Room Auto-Migration digunakan untuk schema changes di future versions:
46.	Version 1 (MVP): Initial schema dengan habits dan habit_logs
47.	Version 2 (jika ada perubahan): Tambah column baru dengan @ColumnInfo(defaultValue)
48.	Setiap migration didokumentasikan dengan @Database annotation
49.	Fallback: Jika auto-migration gagal, gunakan destructive migration dengan warning

Example migration code:

@Database(
  entities = [Habit::class, HabitLog::class],
  version = 2,
  autoMigrations = [AutoMigration(from = 1, to = 2)]
)

7.3.3 Streak Calculation (Repository Level)
suspend fun calculateStreak(habitId: Long): Int {
  val frequency = habitDao.getHabitById(habitId).frequency
  var streak = 0
  var currentDate = LocalDate.now()
  
  while (true) {
    val log = habitLogDao.getLogForDate(habitId, currentDate.toString())
    if (log == null || !log.completed) break
    streak++
    currentDate = when (frequency) {
      DAILY -> currentDate.minusDays(1)
      WEEKLY -> currentDate.minusWeeks(1)
    }
  }
  return streak
}

Cached di ViewModel dengan StateFlow untuk performance.

7.4 Performance Optimization
•	LazyColumn untuk habit list (lazy loading, recycle views)

•	Image assets di WebP format untuk smaller APK size
•	ProGuard/R8 enabled untuk code shrinking di release build

7.5 Error Handling Strategy
3-tier error handling:
55.	Data Layer: Try-catch di repository, return Result<T> sealed class
56.	Domain Layer: Validate business rules, return Either<Error, Success>
57.	Presentation Layer: Convert errors to user-friendly messages di ViewModel

Error types:
•	DatabaseError: Room query failures → Show generic error + retry button
•	ValidationError: Invalid input → Show inline error below field
•	NotificationError: Permission denied → Show settings redirect dialog
